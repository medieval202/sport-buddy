# 系统需求实现对照

## 1. 角色与业务边界

| 角色 | 已实现能力 |
| --- | --- |
| 学生 | 注册登录、维护运动档案、发布活动、加入或退出组队、查看五维匹配、邀请搭子、预约和取消场地 |
| 管理员 | 活动审核与驳回、学生信用分调整、账户启停、校园公告发布、实时通知 |

权限边界由 Spring Security 和 JWT 保护。公开接口仅限登录注册、首页静态资源与公告读取，管理员接口统一位于 `/api/admin/**`。

## 2. 功能需求

### 基础功能

- 注册登录：用户名唯一校验、BCrypt 密码散列、JWT 签发和请求过滤器鉴权。
- 个人信息：昵称、运动偏好、运动水平、校区、空闲时段、经纬度和信用分。

### 核心功能

- 运动组队：学生提交活动后进入 `PENDING` 状态；管理员通过后进入 `APPROVED` 状态；其他学生可按人数和信用门槛加入。
- 实时找搭子：学生提交运动项目、时间窗、水平与当前位置后进入在线匹配池；系统立即与在线意图进行五维评分，撮合成功后向双方推送通知，未匹配时可保持搜索或取消。
- 场地预约：查询场地、查看某日占用时段、创建预约、取消预约；同一场地同一日期禁止时间重叠。
- 信用积分：用户默认 100 分；活动可设置最低信用门槛；管理员可调整信用和停用账户；信用分参与推荐加权。

### 管理功能

- 用户管理：查询全部学生、修改信用分、启用或禁用账户。
- 活动审核：查看待审核列表、通过或填写原因驳回，审核结果通过 WebSocket 通知发起人。
- 公告发布：管理员发布公告后实时推送给在线用户。

## 3. 算法需求

系统把以下特征量化后求和：

| 特征 | 数据来源 | 量化规则 |
| --- | --- | --- |
| 运动项目 | 候选人偏好、活动项目 | 命中 35 分，否则 0 分 |
| 时间窗 | 活动开始时间、候选人空闲时段 | 命中 25 分，否则 0 分 |
| 物理距离 | 双方经纬度 | Haversine 距离分段得 20/17/14/8/0 分 |
| 运动水平 | 候选人水平、活动建议水平 | 同级 10 分，相邻 6 分，相差两级 2 分 |
| 信用分 | 候选人信用分 | 每 10 分折算 1 分，最高 10 分 |

总分为 100 分。低于活动信用门槛的候选人不会进入推荐列表，最终结果按分数降序输出。

## 4. 非功能需求

- 并发处理：场地预约事务对目标场地加悲观写锁，确保同一场地的冲突检查不会并发穿透。
- 安全性：登录使用 JWT；密码使用 BCrypt；接口按角色授权；账户禁用后新请求无法继续通过鉴权；WebSocket 握手也需要 JWT。
- 实时性：活动审核、加入活动、邀请搭子、公告发布通过 WebSocket 推送在线消息。
- 实时匹配：WebSocket 心跳维护在线状态；匹配成功、匹配取消均通过长连接即时推送；等待期间每 5 秒推送在线人数、搜索人数和等待时长，前端配合雷达扫描与脉冲扩散动画降低等待焦虑。
- 可维护性：Controller、Service、Repository、DTO、Model 分层，核心业务规则集中在服务层。
- 可测试性：提供 MockMvc 集成测试和独立演示数据，便于验收核心流程。

## 5. 原型取舍

原型聚焦主要业务闭环，以 H2 内存数据库降低部署成本。正式系统建议迁移 PostgreSQL/MySQL，增加活动签到、信用变更流水、通知历史、预约审核、定时清理、限流、操作审计和地理空间索引。
